# Setup Wizard Design Spec

**Date**: 2026-05-19
**Status**: Approved
**Branch**: feature/accessibility-improvements

---

## Overview

A guided setup wizard for Oh my tmux! that walks users through configuration via
plain shell prompts, writes structured settings to a new `tmux.toml` config layer,
and adapts its interaction style for screen reader users. The wizard runs
standalone, is offered at the end of `install.sh`, and is accessible via a tmux
keybinding (`prefix + W`) for re-running at any time.

## Goals

1. Lower the barrier to configuring Oh my tmux! (no manual file editing required)
2. Provide a first-class accessible setup experience for screen reader users
3. Introduce structured TOML configuration as the primary settings format
4. Preserve `.tmux.conf.local` as the power-user escape hatch for raw tmux commands
5. Support migration from existing `.tmux.conf.local` variable-based configs

## Non-Goals

- Full TOML spec compliance (no nested tables, arrays-of-tables, inline tables)
- ncurses/TUI widgets (accessibility constraint)
- Replacing the embedded shell engine in `.tmux.conf`

## Architecture

### New Files

| File | Purpose |
|------|---------|
| `setup-wizard.sh` | Main wizard script (~400-600 lines POSIX sh) |
| `tmux.toml.default` | Template TOML with all settings, comments, and defaults |

### Modified Files

| File | Change |
|------|--------|
| `.tmux.conf` | Add `_parse_toml()` awk function; source `tmux.toml` before `.tmux.conf.local` |
| `install.sh` | Offer wizard at end of install |
| `.tmux.conf.local` | Strip `tmux_conf_*` variable assignments; keep raw tmux commands, `#!important` overrides, TPM section |
| `README.md` | Document wizard, new config structure, migration path |

### Config Precedence (lowest to highest)

1. Defaults embedded in `.tmux.conf` shell script
2. `tmux.toml` (structured settings via awk TOML parser)
3. `.tmux.conf.local` (raw shell/tmux overrides, `#!important`)

**Precedence rule**: `.tmux.conf.local` always wins. If a user sets
`tmux_conf_theme_colour_1="#ff0000"` in `.tmux.conf.local`, it overrides the
same value from `tmux.toml`. The TOML file is sourced first (converted to shell
variables), then `.tmux.conf.local` is sourced second and can overwrite any
variable. This is identical to how defaults work today: defaults are set in the
embedded script, then `.tmux.conf.local` overwrites them.

**What lives where**:
- `tmux.toml`: all `tmux_conf_*` declarative settings (the wizard manages this)
- `.tmux.conf.local`: raw `set -g`, `bind`, `unbind`, custom shell, `#!important`
  lines, and any `tmux_conf_*` overrides the user wants to hardcode beyond TOML

### File Location Detection

The wizard and parser follow the same priority as the existing config:
1. `$XDG_CONFIG_HOME/tmux/tmux.toml`
2. `~/.config/tmux/tmux.toml`
3. `~/.tmux.toml` (alongside `~/.tmux.conf`)

The active location matches wherever `tmux.conf` was found.

**Wizard Q column**: which wizard mode asks this question.
- `quick`: asked in quick setup mode
- `full`: asked in full setup mode only
- `-`: not directly asked (set by preset or palette selection)
- `quick(palette)`: set as a group by palette selection in quick mode

**Migration Class column**:
- `migrate`: value is extracted from `.tmux.conf.local`, written to TOML, removed from local
- `leave`: value uses tmux `%if` conditionals or complex shell expressions;
  left in `.tmux.conf.local` as an override (the TOML value serves as fallback)

### Wizard-Only Settings (not in TOML)

These wizard questions produce raw tmux commands written to `.tmux.conf.local`
because they are not `tmux_conf_*` variables:

| Wizard Question | Produces in `.tmux.conf.local` |
|---|---|
| Prefix key (C-a) | `set -gu prefix2` + `unbind C-a` + `unbind C-b` + `set -g prefix C-a` + `bind C-a send-prefix` |
| Mouse support (on) | `set -g mouse on` |

These are written as raw tmux commands with `#!important` suffix to prevent the
framework from overwriting them. The wizard writes them to a clearly marked
section at the end of `.tmux.conf.local`:

```
# -- wizard-managed settings ---------------------------------------------------
# DO NOT EDIT: regenerated by setup-wizard.sh on each run
set -g mouse on #!important
# -- end wizard-managed settings -----------------------------------------------
```

**Idempotent reruns**: On subsequent runs, the wizard replaces the entire block
between the start marker (`# -- wizard-managed settings`) and end marker
(`# -- end wizard-managed settings`). It never appends a second block. If the
markers are not found (manual deletion), the wizard appends a fresh block at the
end of the file.

## TOML Parser (`_parse_toml`)

An awk function embedded in the `.tmux.conf` shell script. Constraints:

- POSIX awk compatible (mawk, gawk, nawk)
- Handles: `[section]` headers, `key = value`, `key = "quoted string"`,
  `# comments`, blank lines, booleans (`true`/`false`), integers, quoted strings
- Does NOT handle: nested tables (`[a.b]`), arrays (`[1, 2]`),
  arrays-of-tables (`[[section]]`), inline tables (`{a = 1}`),
  multi-line strings (`"""..."""`)
- Output: shell variable assignments on stdout, one per line:
  `tmux_conf_theme_colour_1="#080808"`
- Malformed lines: emit a warning via stderr (which becomes a tmux
  `display-message` at runtime), skip the line, continue parsing
- Empty/missing file: silently produce no output (defaults apply)
- Unknown section+key combinations (not in mapping table): emit warning, skip

### Value Handling Rules

Values in `tmux.toml` may contain characters that are special in shell or TOML
contexts. The parser applies these rules:

| Value Type | TOML Syntax | Output |
|---|---|---|
| Quoted string (simple) | `key = "value"` | `var=value` (no special chars, bare) |
| Quoted string (special) | `key = "#080808"` | `var="#080808"` (has `#`, quoted) |
| Bare string | `key = value` | `var=value` (trimmed) |
| Boolean | `key = true` / `key = false` | `var=true` / `var=false` |
| Integer | `key = 5000` | `var=5000` |
| Inline comment | `key = "val" # comment` | `var=val` (comment stripped) |
| Equals in quotes | `key = "a=b"` | `var=a=b` (no special chars beyond `=`) |
| Dollar references | `key = "$tmux_conf_theme_colour_2"` | `var="$tmux_conf_theme_colour_2"` (has `$`, quoted) |
| Tmux formats | `key = "#{prefix}"` | `var="#{prefix}"` (has `#`, quoted) |
| Space in value | `key = "hello world"` | `var="hello world"` (has space, quoted) |
| Empty quoted | `key = ""` | `var=` (empty) |

**Critical rule**: The parser does NOT interpret `$variable` references or tmux
`#{format}` strings. These are passed through as literal text. The shell engine
in `.tmux.conf` performs variable expansion when it later reads these values.

**Quoting in output**: All values that contain spaces, `#`, `$`, or shell
metacharacters are output wrapped in double quotes: `var="value"`. Values that are
plain alphanumeric, boolean keywords, integers, or simple identifiers (no special
chars) are output bare: `var=value`. Rule: if the value was quoted in TOML, or if
the stripped value contains any of `[ #$;|&(){}]`, quote it in output.

### Enum and Boolean Conversion

Several `tmux_conf_*` variables use string enums (`enabled`/`disabled`) rather
than booleans (`true`/`false`). The TOML file uses the native format for each:

| Shell Variable Pattern | TOML Value Type | Example TOML | Output |
|---|---|---|---|
| `tmux_conf_theme` | string enum | `enabled = "enabled"` | `tmux_conf_theme=enabled` |
| `tmux_conf_accessibility` | string enum | `enabled = "disabled"` | `tmux_conf_accessibility=disabled` |
| `tmux_conf_accessibility_keys` | string enum | `keys = "disabled"` | `tmux_conf_accessibility_keys=disabled` |
| `tmux_conf_copy_to_os_clipboard` | tri-state | `copy_to_os_clipboard = false` | `tmux_conf_copy_to_os_clipboard=false` |
| `tmux_conf_*_retain_current_path` | tri-state | `new_pane_retain_current_path = true` | `tmux_conf_new_pane_retain_current_path=true` |
| `tmux_conf_highlight_focused_pane` | boolean | `highlight_focused_pane = false` | `tmux_conf_theme_highlight_focused_pane=false` |

**Tri-state values** (`true`/`false`/`disabled`): stored as bare keywords in TOML.
The parser passes them through literally. The `_is_true`, `_is_enabled`,
`_is_disabled` helpers in the shell engine handle interpretation.

**String enums** (`enabled`/`disabled`): stored as quoted strings in TOML.
The parser strips quotes and outputs the bare string.

The wizard presents user-friendly labels ("Enable accessibility? [y/N]") and
maps the answer to the correct TOML representation internally.

### Parser pseudocode

```
BEGIN { section = "" }
/^[[:space:]]*#/ { next }          # skip comments
/^[[:space:]]*$/ { next }          # skip blank lines
/^\[([a-z_]+)\]/ {                 # section header
    section = captured group
    next
}
/^([a-z_0-9]+)[[:space:]]*=/ {    # key = value
    key = captured group before =
    raw = everything after =, trimmed
    # if raw starts and ends with ", strip outer quotes
    #   (inner content is literal, including #, =, $, #{})
    # else strip inline comment (first # preceded by space, outside quotes)
    # look up section+key in mapping table
    # if not found: warn to stderr, next
    # determine output quoting (add " if value has spaces or #)
    print mapped_varname "=" maybe_quoted_value
}
```

### Entry Points

1. **Standalone**: `./setup-wizard.sh` (or full path)
2. **Post-install**: `install.sh` offers at the end: "Run setup wizard? [Y/n]"
3. **Tmux keybinding**: `prefix + W` opens wizard in a new tmux window

### Initial Questions

```
1. "Are you using a screen reader? [y/N]"
   -> Sets SR_MODE=1 (adapts all subsequent output)

2. "Choose setup mode:"
   1. Quick setup (~2 minutes, essential settings)
   2. Full setup (~5-10 minutes, all settings)
   3. Choose a preset
   4. Choose a preset, then customize
```

### Screen Reader Adaptations (SR_MODE=1)

When active:
- Each prompt reads: "Question N of M: ..."
- Choices are explicitly numbered: "1. option. 2. option."
- After each answer: "You chose: [value]. Moving to next question."
- No emoji, no box-drawing characters, no decorative output
- Summary at end is sequential plain text
- Extra pause after each section transition

When inactive (SR_MODE=0):
- Colored output (if terminal supports it)
- Compact formatting
- Progress indicator: "[3/8]"
- Summary as aligned table

### Quick Setup Flow (~8 questions)

1. Prefix key: C-b (default) / C-a / custom -> writes raw tmux to `.tmux.conf.local`
2. Mouse support: on / off -> writes raw tmux to `.tmux.conf.local`
3. Theme palette: dark / light / ansi / accessible-dark / accessible-light -> sets `[theme].colour_1`..`colour_17` in TOML
4. Clipboard to OS: on / off -> sets `[clipboard].copy_to_os_clipboard` in TOML
5. Accessibility mode: enabled / disabled -> sets `[accessibility].enabled` in TOML
6. 24-bit colour: auto / true / false -> sets `[display].colour_24b` in TOML
7. Pane path retention: on / off -> sets `[general].new_pane_retain_current_path` in TOML
8. TPM plugin auto-update: on / off -> sets `[plugins].update_on_launch` in TOML

### Full Setup Flow

All quick setup questions plus additional detail:
- Session/window path retention (2 additional questions; pane was already in quick)
- SSH reconnect (2 questions)
- Status bar left/right content
- Each indicator symbol
- Battery display settings
- Clock style (12h/24h)
- urlscan options
- Separator style (powerline / ASCII / custom)

### Presets

| Preset | Description |
|--------|-------------|
| `minimal` | Stock bindings, no mouse, default dark theme, no plugins, no clipboard |
| `power-user` | C-a prefix, mouse on, clipboard on, 24b colour, path retention on |
| `accessible` | Accessibility enabled, keys enabled, accessible-dark theme, display_time=5000, visual activity on, ASCII separators |

### Review Step

Before writing, the wizard displays all settings that differ from defaults:

```
=== Review your settings ===

Prefix key: C-a
Mouse: on
Theme: accessible-dark
Clipboard: on
Accessibility: enabled
[... only non-default values shown ...]

Apply these settings? [Y/n/edit]
- Y: write and apply
- n: discard and exit
- edit: go back to modify specific settings
```

### Write and Apply

1. If `tmux.toml` exists, copy to `tmux.toml.bak`
2. Write new `tmux.toml` atomically (write to `.tmux.toml.tmp`, then `mv`)
3. If running inside tmux, offer to reload: "Reload tmux config now? [Y/n]"
4. Print completion message with rollback instructions:
   "Config saved. To undo: mv tmux.toml.bak tmux.toml && tmux source <conf-path>"
   (where <conf-path> is the detected $TMUX_CONF value, e.g., ~/.config/tmux/tmux.conf)

## Migration from `.tmux.conf.local`

When the wizard detects `tmux_conf_*` variables in the active conf.local file:

```
"Existing configuration detected in .tmux.conf.local.
 Migrate settings to tmux.toml? [Y/n]"
```

**File detection**: The wizard checks for the conf.local file in the same location
priority as the main config:
1. `$XDG_CONFIG_HOME/tmux/tmux.conf.local`
2. `~/.config/tmux/tmux.conf.local`
3. `~/.tmux.conf.local`

The wizard uses `$TMUX_CONF_LOCAL` if set (matching the framework's own detection),
otherwise probes in priority order.

If yes:
1. Back up conf.local to `<same-path>.pre-toml` (e.g., `tmux.conf.local.pre-toml`)
2. Parse all `tmux_conf_*=value` lines using regex extraction
3. Map them to TOML sections/keys using the mapping table
4. Write `tmux.toml` to the same directory as the conf.local file
5. Remove migrated variable lines from conf.local
6. Preserve all other content (raw tmux commands, comments, `#!important` lines)

If no: wizard proceeds normally; both files coexist (`.tmux.conf.local` wins
per precedence rules above; TOML values serve as defaults that local overrides).

### Migration Line Classification

Each line in `.tmux.conf.local` is classified into one of these categories:

| Line Pattern | Classification | Action |
|---|---|---|
| `tmux_conf_*=<simple_value>` | migratable | Extract value, write to TOML, remove line |
| `tmux_conf_*="<simple_value>"` | migratable | Extract quoted value, write to TOML, remove line |
| `#tmux_conf_*=...` | commented-out | Leave in place (user intentionally disabled) |
| `tmux_conf_*=<value> #!important` | important-override | Leave in place (user override, takes precedence over TOML) |
| `%if ...` / `%endif` blocks | conditional | Leave entire block in place |
| `tmux_conf_*="$(shell_cmd)"` | shell-expression | Leave in place with warning |
| `tmux_conf_*="#{tmux_format}"` | tmux-format | Migratable (passed through literally) |
| `tmux_conf_*="$tmux_conf_*"` | variable-ref | Migratable (passed through literally) |
| `set -g ...` / `bind ...` | raw-tmux | Leave in place |
| `# comment` / blank | structural | Leave in place |
| `tmux_conf_UNKNOWN=...` | unmapped | Leave in place with warning |

**Deterministic handling rules:**
- Lines inside `%if`/`%endif` blocks: never migrate, always leave. The wizard
  cannot represent conditional logic in flat TOML.
- Shell expressions (`$(...)`, backticks): never migrate. Print warning:
  "Line N uses shell expansion; left in .tmux.conf.local as override."
- Duplicate keys: if the same `tmux_conf_*` appears multiple times, migrate only
  the LAST occurrence (the one that wins in shell evaluation). Remove all earlier
  occurrences.
- Lines with `#!important`: never migrate. These are explicit user overrides.
- Unrecognized `tmux_conf_*` variables (not in the mapping table): leave in place,
  emit warning: "Unknown setting: tmux_conf_foo_bar (not migrated)."

### Migration Report

After migration, print a summary:
```
Migration complete:
  Migrated: 34 settings to tmux.toml
  Left in place: 8 lines (3 conditional, 2 shell expressions, 2 #!important, 1 unknown)
  Backup: .tmux.conf.local.pre-toml
```

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Existing `tmux.toml` | Pre-fill wizard answers with current values; back up before overwrite |
| TOML parse error at runtime | `display-message` warning with line number; skip line; continue with defaults |
| Wizard interrupted (Ctrl+C) | No partial writes (atomic write at end only) |
| tmux not running | Wizard works fine standalone; changes apply on next start |
| Read-only filesystem | Detect early, fail with clear message |
| Malformed `.tmux.conf.local` during migration | Skip unparseable lines, report count, continue |

### Rollback

- Before every write, `tmux.toml` is copied to `tmux.toml.bak`
- Completion message includes rollback command
- At most one `.bak` file exists (latest backup only)

## Keybinding

The binding is set dynamically in `_apply_bindings` where the clone path is known.
The framework already resolves the clone directory internally (the embedded script
runs from there). The binding uses the same `#{TMUX_CONF}` pattern as all other
bindings in the framework:

```sh
# Inside _apply_bindings:
# #{TMUX_CONF} is a symlink to <clone>/.tmux.conf, so resolving its real path
# and taking dirname gives us the clone root where setup-wizard.sh lives.
tmux bind W run-shell "sh -c 'exec \"\$(cd \"\$(dirname \"\$(readlink \"\$TMUX_CONF\" 2>/dev/null || printf \"%s\" \"\$TMUX_CONF\")\")\"; pwd)/setup-wizard.sh\"'"
```

**How it works**: This is the same pattern used by all other Oh my tmux! bindings
that need to find the clone. `$TMUX_CONF` is a tmux environment variable
(set at lines 153-154 of `.tmux.conf`) that points to the symlink. `readlink`
resolves it to the clone's `.tmux.conf`; `dirname` gives the clone root.

**macOS compatibility**: macOS `readlink` (without `-f`) resolves one level of
symlink, which is sufficient since install.sh creates a single-level symlink.
The `|| printf "%s" "$TMUX_CONF"` fallback handles the case where `TMUX_CONF` is
not a symlink (direct file, not symlinked install).

**POSIX compliance**: uses `sh -c` with standard utilities. The wizard itself
handles the "press Enter" prompt with `printf` + `read _`.

**Graceful degradation**: If `setup-wizard.sh` does not exist at the resolved
path, the shell produces a "not found" error in the tmux window. No silent failure.

## Testing Strategy

### TOML Parser Tests (`tests/test_toml_parser.sh`)

- Valid flat TOML: sections, string values, booleans, integers
- Comments and blank lines (ignored)
- Quoted strings with special chars (spaces, `#`, `=`)
- Missing file (empty output)
- Malformed lines (skipped with warning)
- Empty values
- Variable mapping correctness (section+key -> tmux_conf_*)

### Wizard Flow Tests (`tests/test_wizard.sh`)

- Quick setup with mocked stdin: verify generated TOML
- Full setup with mocked stdin: verify all settings present
- Each preset: verify correct TOML output
- Screen reader mode: verify no emoji/decorative chars in stdout
- Review step: verify "edit" loops back
- Ctrl+C: verify no file written
- Existing config: verify pre-fill and backup behavior

### Migration Tests (`tests/test_migration.sh`)

- Standard `.tmux.conf.local`: correct extraction and TOML generation
- Mixed content: variables removed, raw tmux preserved
- Edge cases: `#!important` lines, commented variables, duplicate keys

### Integration Tests

- Round-trip: write TOML, parse with awk, verify shell variables match
- Precedence: TOML value overridden by `.tmux.conf.local` `#!important`
- Reload: source after wizard completes, verify tmux options applied

## Scope and Constraints

- **POSIX sh only** for the wizard (no bashisms)
- **POSIX awk** for the parser (compatible with mawk, gawk, nawk)
- **No external dependencies** beyond what Oh my tmux! already requires
- **No network access** during wizard operation
- **Atomic writes** only (temp file + mv)
- **Backward compatible**: existing `.tmux.conf.local` configurations continue
  to work unchanged if the user never runs the wizard or creates a `tmux.toml`
